# Android performance fixture

This standalone project uses published `opencc-core`, `opencc-platform` and the
selected `opencc-data-s2t` resource ZIP. It builds an R8 release APK with no OpenCC
keep rules. It does not change the production consumer fixture or its size budgets.

After publishing the local artifacts and preparing the pinned native library:

```sh
python3 tools/prepare_android_benchmark.py
ANDROID_HOME=/path/to/android-sdk ./gradlew -p benchmarks/android assembleRelease reportBenchmarkDependencies
python3 tools/verify_android_benchmark.py
python3 tools/run_android_benchmark.py --serial YOUR_EXPLICIT_DEVICE_SERIAL
```

The runner requires at least 30 launches, stops the application before each launch,
and checks that its process is absent. It does not select a default device, create
an emulator or clear device log buffers. Every launch validates the full conversion
against an asset generated by pinned OpenCC, with tofu-risk dictionaries enabled
to match the library default. The corpus is the same 1000-character workload used
by the JVM benchmarks.

JSON records report first resource load and conversion separately, their combined
duration, and warm p50/p95 for 300 conversions after 100 warmups. Device/build/ABI,
thermal status where Android supports it, battery temperature/power state, process
VmHWM and Java/native heap snapshots accompany each launch. The host aggregates
cold timings and per-launch warm quantiles without treating those quantiles as raw
conversion samples. OS filesystem caches can remain warm across fresh processes.

Reports go to `.cache/benchmarks/android/<timestamp>/report.json` and remain partial
if a launch fails. Emulator indicators label a run as `emulator-performance-smoke`.
Measurements from a physical device require an explicitly supplied serial and the
recorded device metadata; building this APK provides no physical-device performance
evidence by itself. The driver also checks that the APK contains s2t assets and no
t2s configuration. Memory includes the Android application process, and heap
snapshots do not represent engine-only retained memory.
